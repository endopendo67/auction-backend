## Анализ механики Telegram Auctions

### Как устроены раунды

Изучив Telegram Gift Auctions, я выделил ключевые особенности:

**Многораундовая структура:** Аукцион делится на несколько раундов. В каждом раунде фиксированное количество участников получает товар — те, кто находится в топе по сумме ставки на момент завершения раунда.

```
Пример: 100 товаров, 3 раунда

┌──────────┬────────────┬─────────────────────────────────┐
│ Раунд 1  │ 5 минут    │ Топ-30 получают товар           │
│ Раунд 2  │ 3 минуты   │ Топ-30 получают товар           │
│ Раунд 3  │ 2 минуты   │ Топ-40 получают оставшееся      │
│          │            │ Остальные → возврат средств     │
└──────────┴────────────┴─────────────────────────────────┘
```

**Сокращение времени:** Каждый следующий раунд короче предыдущего — это создаёт нарастающее напряжение и стимулирует активность.

### Ранжирование участников

Позиция в лидерборде определяется двумя факторами:

1. **Сумма ставки** — основной критерий (выше сумма = лучше позиция)
2. **Время ставки** — при равных суммах приоритет у того, кто поставил раньше

**Важный нюанс:** При повышении ставки сохраняется исходное время первой ставки. Это справедливо — человек, который участвует с самого начала, не должен терять приоритет просто потому, что повысил ставку.

### Anti-sniping механизм

Telegram защищается от "снайперских" ставок в последние секунды:

**Моя реализация:**
- Если ставка сделана в последние 30 секунд раунда — раунд может продлиться
- Шанс продления: 50% (рандомизация, чтобы нельзя было предсказать)
- Продление: +60 секунд
- Ограничение: максимум 1 продление за раунд

Это создаёт неопределённость для "снайперов", но не позволяет бесконечно затягивать раунд.

### Финансовая модель

**Блокировка средств:**
- При размещении ставки сумма блокируется, но не списывается
- При повышении ставки блокируется только разница
- Пользователь не может поставить больше, чем доступно (баланс минус заблокированное)

**После раунда:**
- Победители: заблокированная сумма списывается окончательно
- Проигравшие: если продолжают участие — ставка переносится в следующий раунд
- После последнего раунда: все неиспользованные средства разблокируются

### Принятые допущения

Там, где поведение Telegram неочевидно, я принял следующие решения:

| Вопрос | Моё решение | Обоснование |
|--------|-------------|-------------|
| Можно ли понизить ставку? | Нет | Защита от манипуляций |
| Минимальный шаг повышения? | +1⭐ (настраивается) | Гибкость для разных аукционов |
| Что если участник в топе нескольких раундов? | Получает товар в первом же | Нельзя выиграть дважды |
| Максимальная ставка? | 10,000,000⭐ | Защита от ошибок ввода |

## Архитектурные решения

### Почему атомарные операции вместо транзакций

MongoDB транзакции создают WriteConflict при высокой конкурентности. Вместо этого я использую атомарные операции с условиями:

```typescript
// Блокировка средств — один атомарный запрос
const result = await User.findOneAndUpdate(
  {
    _id: userId,
    // Условие: доступный баланс >= сумма ставки
    $expr: { $gte: [{ $subtract: ['$balance', '$lockedBalance'] }, amount] }
  },
  { $inc: { lockedBalance: amount } },
  { new: true }
);

if (!result) {
  throw new Error('Недостаточно средств');
}
```

**Преимущества:**
- Нет WriteConflict даже при тысячах параллельных запросов
- Атомарность гарантируется на уровне документа MongoDB
- Проще отлаживать

### Real-time через WebSocket

Все обновления приходят через WebSocket:
- Новые ставки
- Обновление лидерборда
- Смена раундов
- Anti-sniping продления

HTTP используется только для первоначальной загрузки данных.

### Кэширование в Redis

- Лидерборд кэшируется на 500ms
- Минимальная победная ставка кэшируется на 500ms
- При высокой нагрузке это снижает количество запросов к MongoDB в 10-20 раз

### Обработка завершения раунда

Победители определяются атомарно через `bulkWrite`:

```typescript
// Один запрос для всех обновлений
await Bid.bulkWrite([
  // Помечаем победителей
  { updateOne: { filter: { _id: bid1Id }, update: { status: 'won', itemNumber: 1 } } },
  { updateOne: { filter: { _id: bid2Id }, update: { status: 'won', itemNumber: 2 } } },
  // Переносим остальных в следующий раунд
  { updateMany: { filter: { auctionId, status: 'active' }, update: { status: 'carried_over' } } },
]);
```

## Запуск проекта

### Требования

- Docker и Docker Compose
- Порты: 80, 27017, 6379

### Установка

```bash
git clone https://github.com/endopendo67/auction-backend.git
cd auction-backend
docker-compose up -d
```

Приложение доступно на http://localhost

### Проверка статуса

```bash
docker-compose ps
```

Все сервисы должны быть `Up (healthy)`.

### Просмотр логов

```bash
docker-compose logs -f app
```

## Тестирование под нагрузкой

### Интерактивное тестирование с ботами

1. Открой http://localhost (или [демо](https://auction-demo.lol))
2. Войди под любым именем
3. Создай аукцион и включи "Симуляция торгов"
4. Наблюдай как боты торгуются в реальном времени

Количество ботов = количество товаров × 3. Например, 10 товаров = 30 ботов.

### Автоматический стресс-тест

```bash
docker-compose exec app npx tsx scripts/stress-test.ts
```

**Параметры теста:**
- 5000 товаров
- 5 раундов по 30 секунд
- 6000 ботов
- ~300 параллельных запросов

**Что проверяется:**
- Целостность балансов (сумма всех балансов должна быть константой)
- Корректность определения победителей
- Отсутствие дублирования товаров
- Работа anti-sniping

**Ожидаемый результат:**
```
✓ 15000 ставок | ✗ 50 ошибок | Avg: 45ms | Success: 99.7%
Победителей: 5000
Ставок в БД: 15000
```

### Проверка anti-sniping

1. Создай аукцион с коротким раундом (60 сек)
2. Дождись последних 30 секунд
3. Сделай ставку
4. С вероятностью 50% раунд продлится на 60 секунд

## API Reference

### Аутентификация

```http
POST /api/auth/login
Content-Type: application/json

{ "username": "player1" }
```

Создаёт пользователя если не существует. Начальный баланс: 10,000⭐

### Аукционы

```http
# Создать аукцион
POST /api/auctions
{
  "title": "NFT Drop",
  "totalItems": 10,
  "startingPrice": 100,
  "roundsConfig": [
    { "itemsToDistribute": 3, "durationMs": 120000 },
    { "itemsToDistribute": 3, "durationMs": 90000 },
    { "itemsToDistribute": 4, "durationMs": 60000 }
  ],
  "createdBy": "user_id"
}

# Запустить с ботами
POST /api/auctions/:id/start
{ "enableBotSimulation": true }

# Сделать ставку
POST /api/auctions/:id/bid
{ "userId": "user_id", "amount": 500 }

# Лидерборд
GET /api/auctions/:id/leaderboard?limit=100

# Победители
GET /api/auctions/:id/winners
```

### WebSocket Events

```javascript
const socket = io({ transports: ['websocket'] });

// Подключиться к аукциону
socket.emit('auction:join', auctionId);

// Получить обновления
socket.on('auction:leaderboard', (data) => { /* ... */ });
socket.on('auction:new_bid', (data) => { /* ... */ });
socket.on('auction:winners', (data) => { /* ... */ });
socket.on('auction:time_extended', (data) => { /* ... */ });
socket.on('auction:event', (event) => { /* round_started, round_ended, etc */ });
```
